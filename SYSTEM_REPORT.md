# Profile Scraping Agent System Report

## System Overview

This is an automated profile scraping system designed to collect professional profiles for specific technology domains. The system searches multiple online sources, extracts structured data, and stores it in an Excel workbook for further analysis.

## System Architecture

### Core Components

1. **Main Orchestration Scripts**
   - `auto_scrape.py`: Runs scraping rounds for predefined technology queries
   - `targeted_scrape.py`: Similar to auto_scrape but with specific technology-sheet mappings
   - `count_complete.py`: Counts complete profiles per technology
   - `segregate.py`: Organizes profiles into technology-specific sheets

2. **Core Scraping Engine** (`skills/profile_scraper/run.py`)
   - Orchestrates the entire scraping process
   - Calls the scraper module to search multiple sources
   - Parses and saves results to Excel

3. **Scraper Module** (`skills/profile_scraper/scraper.py`)
   - Searches multiple sources: SerpAPI, Google CSE, GitHub, Bright Data (LinkedIn)
   - Parses results to extract:
     - Name, Technology, Years of Experience
     - LinkedIn, GitHub, Email, Location
     - Security Clearances, Skill set
   - Handles data validation, deduplication, and USA location filtering
   - Saves profiles to either "Profiles" (complete) or "Incomplete" sheets
   - Runs Hunter.io enrichment on incomplete profiles

### Data Sources

The system searches these sources in parallel:
- **SerpAPI** (Google search) - Primary web search
- **Google CSE** - Supplemental web search
- **GitHub Users** - Developer profiles (location:USA filter)
- **Bright Data LinkedIn** - Professional profiles (requires API key)

### Data Storage Structure

Excel workbook (`skills/output/profiles.xlsx`) contains:

1. **Profiles Sheet** - Complete records with all required fields:
   - Name, Technology, Years of exp, LinkedIn, GitHub, Email, Location, Security Clearances, Skill set

2. **Incomplete Sheet** - Records missing required fields + "Missing Fields" column

3. **Technology-Specific Sheets** - Auto-generated by `segregate.py`:
   - One sheet per technology (e.g., "Cyber Security", "Cloud", "SAP", etc.)
   - Contains only profiles matching that technology

### Required Fields for Completeness

A profile is considered "complete" when it has:
- Name (not empty)
- Location (not empty AND USA-based)
- At least one contact method: Email, LinkedIn URL, or GitHub URL

## How the System Works - Step by Step

### 1. Search Phase
When `run.py` is executed with a query:
- Constructs USA-filtered search queries
- Searches all available sources in parallel (SerpAPI, Google CSE, GitHub, Bright Data)
- Combines and deduplicates results by URL

### 2. Parsing Phase
For each search result, the system parses based on the source:
- **GitHub Results**: Extracts user info from GitHub API (name, email, location, bio, languages, account age for experience)
- **LinkedIn Results**: Uses Bright Data API for structured profile data OR falls back to web parsing
- **Web Results**: Scrapes the actual webpage for contact information

### 3. Data Enhancement
- Extracts technology from skills/bio/text using keyword matching
- Extracts security clearance using regex patterns
- Calculates years of experience from profile data
- Cross-references: GitHub profiles → LinkedIn lookup, LinkedIn profiles → GitHub lookup
- Runs Hunter.io email enrichment on incomplete profiles (limited effectiveness due to domain restrictions)

### 4. Storage & Validation
- Validates USA location (rejects non-USA profiles)
- Checks for duplicates (by email, LinkedIn, or GitHub URL)
- Determines if profile is complete (has name, USA location, AND at least one contact method)
- Saves to appropriate sheet:
  - **Profiles**: Complete records
  - **Incomplete**: Missing required fields (with "Missing Fields" column)
- Technology-specific segregation happens separately via `segregate.py`

### 5. Enrichment Phase
After each scraping round:
- Runs Hunter.io on profiles missing email in the Incomplete sheet
- Promotes profiles to Profiles sheet when all required fields are satisfied

## Current Limitations & Observations

### 1. Technology Classification Issues
- The system creates separate sheets for "Cyber Security" and "Cybersecurity" due to slight naming variations
- Some technologies show 0 complete profiles despite having entries (SAP, Snowflake) - these likely lack complete contact information

### 2. Data Quality Challenges
- Many profiles lack complete contact information (hence end up in Incomplete sheet)
- Technology detection relies on keyword matching which may not be precise
- Security clearance extraction is dependent on explicit mentions in profile text

### 3. Source Limitations
- Bright Data LinkedIn requires paid API key (may not be configured)
- Hunter.io enrichment limited by domain restrictions (blocks LinkedIn/GitHub domains)
- GitHub API has rate limits without authentication token
